# Sneaky Surfer

A lightweight browser-based proxy inspired by Ultraviolet/Scramjet patterns, designed for Netlify Functions with minimal dependencies.

## Features

- URL + search query handling (DuckDuckGo fallback)
- Netlify Function proxy for HTML/CSS/JS/images/fonts/binary assets
- HTML/CSS rewriting engine for static resources and navigation links
- Runtime injection that patches `fetch` + `XMLHttpRequest`
- Navigation kept inside the proxy iframe + History API syncing
- Supabase browsing history logging (`url`, `title`, `search_query`)
- Basic in-memory GET response cache in the proxy function
- Clean single-page UI

## Project structure

- `public/index.html` — Main UI shell + iframe viewer
- `public/main.js` — Navigation logic, History sync, Supabase logging
- `public/rewrite.js` — URL parsing and proxy URL generation
- `public/runtime.js` — Client-side runtime request interception
- `netlify/functions/proxy.js` — Proxy + rewrite pipeline + caching
- `netlify.toml` — Netlify build/redirect configuration

## Local development

### Option A: Netlify CLI (recommended)

```bash
npm i -g netlify-cli
netlify dev
```

Open `http://localhost:8888`.

### Option B: Static preview only

```bash
python -m http.server 8080 -d public
```

This lets you preview the UI, but the `/api/proxy` function will not run.

## Netlify deployment

1. Push this repository to GitHub.
2. In Netlify, import the repository.
3. Build settings are auto-detected from `netlify.toml`:
   - Publish directory: `public`
   - Functions directory: `netlify/functions`
4. Deploy.

## Supabase setup

The frontend already includes:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`

Create this table in Supabase:

```sql
create table if not exists public.browsing_history (
  id bigint generated by default as identity primary key,
  url text not null,
  title text,
  search_query text,
  created_at timestamptz not null default now()
);
```

Enable RLS + policy as needed for your project.

## MCP (optional development aid)

If Supabase MCP is connected, you can inspect schema compatibility and evolve SQL faster during development. The app itself does **not** depend on MCP at runtime.

## Security notes

This is a development-oriented proxy implementation. Before production use, add:

- domain allow/block lists
- robust SSRF protection
- abuse/rate limiting
- authentication and per-user history ownership
- stricter header/cookie controls
